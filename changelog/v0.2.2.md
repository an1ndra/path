# v0.2.2

Supersedes `v0.2.0` and `v0.2.1`, neither of which completed: both pushed a container image
and then stopped at the vulnerability scan, so no GitHub release or notes were published
for either tag.

`v0.2.1` fixed the vulnerabilities; it failed because the workflow passed the Trivy ignore
file under the wrong input name (`ignorefile` instead of `trivyignores`), which the action
only warns about, so the scan ran without the exceptions and failed on the two accepted
CVEs.

Adds the dependency updates that scan demanded, and the workflow input that makes them
take effect. Everything else since the `v0.1.0` tag: the gateway gains a second routing strategy, guardrails,
an end-user billing axis, a semantic cache, Azure OpenAI and a Helm chart — plus the
fixes from a twelve-point security and billing audit.

## Added

### Routing and model selection

- **Adaptive routing.** A route can declare `strategy`: `priority` (the default, unchanged),
  `fastest` (ordered by an exponentially weighted latency) or `cheapest-viable` (cheapest
  route under a `latency_slo_ms`, the rest demoted to fallback). Route views expose
  `ewma_latency_ms` and `ewma_error_rate` so the decision is auditable, and `provider.order`
  still overrides any strategy.
- **Operator-defined aliases.** `GET/POST /admin/aliases` stores an ordered chain
  (`prod-chat` → `claude-sonnet-4.5`, then `gpt-4o`). Chains are validated at write time —
  an unknown model, a self-reference or more than ten hops is a 400, so a broken alias
  cannot become a 500 on a customer request. The four computed aliases (`cheap`, `fast`,
  `long-context`, `vision`) are unchanged.

### Billing and limits

- **End-user attribution.** `end_user` (or OpenAI's `user`) is stored on every usage row
  and indexed, `/v1/usage` returns a per-end-user breakdown, `/admin/usage` and the CSV
  export filter by it, and a key can cap each customer with `end_user_daily_limit_usd` —
  reserved with an atomic conditional update, so concurrency cannot overshoot.
- **Project rate limits.** Projects carry `rpm_limit` and `max_concurrent_requests`,
  enforced in addition to each key's caps, and shared across replicas through the Valkey
  limiter.
- **Project budget alerts.** `project.budget_low` and `project.budget_exhausted` fire once
  per project, window and period.
- **`POST /v1/tokens/count`.** Free but authenticated: reports prompt tokens and whether the
  prompt fits, counting tool definitions, which is where estimates are usually wrong.
- **Idempotent embeddings.** `/v1/embeddings` honours `Idempotency-Key`; a retried batch is
  no longer billed twice.

### Safety and privacy

- **Guardrails.** PII redaction for prompt logs (on by default) and optionally before send,
  plus opt-in moderation passthrough that refuses a flagged prompt with 400
  `content_flagged`. `GET /admin/settings` reports what is active.
- **Semantic cache tier.** With `semantic_cache_enabled` on a route and
  `GATEWAY_SEMANTIC_MODEL` set, a near-duplicate prompt can reuse a stored completion,
  under the same `temperature: 0`, tool-free, per-key rules as the exact cache.

### Providers and deployment

- **Azure OpenAI.** Setting `api_version` on a provider puts the deployment in the path, the
  version in `?api-version` and the credential in the `api-key` header, for chat,
  embeddings, moderation and the probe.
- **Helm chart** in `deploy/helm/path`: drain-aware grace period enforced at render time,
  HPA with a custom-metric hook, PDB, optional Postgres and Valkey, ServiceMonitor.
- **Per-provider health** at `/actuator/health/providers`; overall health only reports
  OUT_OF_SERVICE when every enabled provider is circuit-open.

## Fixed

The post-0.1.0 audit found twelve issues; all are fixed:

- `models/sync` imported unpriced routes enabled, serving inference for free.
- 500 responses returned internal exception messages; they now return a reference id and
  log the detail server-side.
- Chunked request bodies bypassed the size limit; reading is now counted and 413s.
- The demo API key was created by default, including in the `prod` profile.
- A large `max_tokens` could reserve credit the call would never use.
- Reservation now uses the expected cost while still refusing when it does not fit.
- `/v3/api-docs` was served in production; off in the `prod` profile.
- The in-memory rate-limit windows were never evicted.
- Release tags were not verified to be on `main`.
- `UpstreamClient` allocated an `ObjectMapper` per error.
- Project filters were missing from `/admin/usage`, `/admin/stats` and the CSV export.
- Admin auth had no lockout; ten failures in five minutes now return 429.

Also fixed: the end-user cap was skipped for keys without a credit limit, and `api_version`
was ignored on provider `PATCH`.

## Security

- **Tomcat 10.1.55 → 10.1.62** and **Netty 4.1.135 → 4.1.141**, both of which Spring Boot
  3.5.16 still pins and both of which carry CRITICAL advisories. Overridden in the pom
  rather than by moving the framework version; drop the overrides when Boot manages them.
- **Two Spring Framework CVEs are accepted, with a deadline.** `CVE-2026-47884` (RCE via
  `XsltView` path limitation) and `CVE-2026-47890` (SSE corruption during view rendering)
  are fixed only in Spring Framework 7.0.9, which means Spring Boot 4. Path registers no
  view resolver and renders nothing through a `View`, so neither path is reachable. They
  are listed in `.trivyignore.yaml` with a `statement` and an `expired_at` of 2027-02-01,
  after which the release gate fails again until they are revisited.

- Every GitHub Action is pinned to a commit SHA; a mutable tag can be repointed at any
  commit and would run with this repository's token.
- Master key rotation (`POST /admin/rotate-master-key`) re-encrypts stored credentials
  before switching the active key.
