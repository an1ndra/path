# v0.2.3

The largest release since v0.1.0: a Spring AI adapter module, native Gemini on AI Studio and
Vertex, a daily digest, shared circuit state for clusters, and the alerting and security
work that had accumulated on `Develop` since v0.2.2.

Everything is additive for existing deployments. Two optional switches are worth a look:
`GATEWAY_SHARED_STATE_BACKEND=valkey` for clusters (see Changed) and the opt-in Postgres
partitioning (see Database).

## Added

### Spring AI adapter

- **`path-spring-ai`**, published as `io.github.an1ndra:path-spring-ai`. A `ChatModel` and
  `EmbeddingModel` over the gateway: messages, options, tool definitions and tool responses,
  non-streaming tool calls, SSE content streaming, and `Idempotency-Key` when a caller
  retries. `X-Path-Cache`, `X-Gateway-Provider` and `X-Gateway-Cost-Usd` land in the
  `ChatResponse` metadata; a gateway error surfaces as `PathException` with the status and
  the gateway's code. See [`docs/SPRING-AI.md`](docs/SPRING-AI.md).
- The build is now a reactor: `path` (the gateway, unchanged coordinates) and
  `path-spring-ai` are sibling modules under a `path-parent` POM. The gateway does not
  depend on Spring AI, and the container image still contains only the gateway.

### Providers

- **Native Gemini** for AI Studio and Vertex (`GEMINI` and `VERTEX` provider types) on
  `generateContent`. `thinkingConfig` (or `reasoning_effort`) and `safetySettings` are
  honoured instead of dropped; thinking tokens are billed as output and broken out as
  `reasoning_tokens`; `cachedContentTokenCount` is priced as cache reads. A blocked prompt
  is 400 `content_blocked` naming the safety category, and a parameter Gemini cannot honour
  is 422 `unsupported_parameter` — the same contract the Anthropic adapter keeps.
- **Vertex credentials**: a service-account JSON in the encrypted credential column, an
  RS256 assertion exchanged for a cached OAuth token, and `project`/`location` on the
  provider row.

### Metering and reporting

- **Daily digest email** at `GATEWAY_DIGEST_CRON` (default 08:00): yesterday's requests with
  the day-over-day delta, spend, tokens with the cache hit ratio, failures with the top
  error code, the slowest model's p95, top spend and any parked provider. Silent without a
  mail channel; nothing is sent for an empty day. `POST /admin/digest/test` renders it on
  demand.
- **Bucketed time series** on `GET /admin/stats?bucket=1h|5m|1m|1d`: per-bucket requests,
  cost, failures and p95 latency from one query, zero-filled and capped at 500 points.
  Omitting `bucket` returns the previous response unchanged.
- **Archive slice**: `/admin/usage/export` accepts `from`/`to`, so the exact range a
  retention purge will delete can be captured for finance.
- **Semantic cache hits are counted from usage rows** (`cache_tier` column) instead of a
  process-local counter, so the number survives a restart and matches across replicas.

### Operations

- **Prometheus rules** in `deploy/prometheus/path-rules.yml`: fallback rate, cache hit ratio
  against its 7-day average, spend rate, 5xx rate and providers parked for 15 minutes, each
  with a `runbook` annotation. The Helm chart renders them with `prometheusRule.enabled`.
- **New metrics**: `path_errors_total{provider,class,code}`, `path_fallbacks_total`,
  `path_provider_circuit_open` and `path_alerts_sent_total{channel,outcome}`.
- **Scopes in `/admin/settings`**: `subject` and `scopes` (plus `can_write`) for both token
  and proxy auth, so a console can hide write actions instead of discovering a 403.
- **Email alerting**: `GATEWAY_ALERT_EMAIL_TO` plus `SPRING_MAIL_*` sends every alert by
  mail; `POST /admin/alerts/test` reports which channels are configured; `GET/PUT
  /admin/mail-settings` moves the SMTP settings into the console (password encrypted and
  write-only).
- **SSO proxy auth** for the admin API: an authenticating proxy can inject an identity
  header instead of a pasted token. Read [`docs/SSO.md`](docs/SSO.md) first — it is only
  safe when the gateway is unreachable except through that proxy.
- **Dokploy deployment assets**, including a Traefik router and a container health check.

## Changed

- **Webhook alerts retry** up to three times with jittered exponential backoff, only on 429,
  5xx and connect/timeout, honouring `Retry-After`. Both webhook and email run on bounded
  queues; a full queue drops and counts instead of blocking the request or growing without
  limit.
- **Provider error-rate alert**: a one-minute check over the routing EWMA fires
  `provider.error_rate_high` when a provider's rate stays above
  `GATEWAY_ALERT_ERROR_RATE` (0.25) with enough samples, and `provider.error_rate_normal`
  when it recovers. This catches the provider that fails 30% of the time without ever
  tripping the consecutive-failure breaker.
- **Cluster state**: `GATEWAY_SHARED_STATE_BACKEND=valkey` shares circuit-breaker and
  in-flight state across replicas. Exactly one replica claims the half-open probe, an OPEN
  entry expires even if the replica that opened it dies, and a killed pod's concurrency
  permits age out. Memory remains the default and is unchanged.
- **Release images are scanned before they are named.** The workflow pushes only
  `sha-<commit>`, scans it, and promotes that digest to the version and `latest` with
  `imagetools`; a failed scan no longer burns a version number.
- **Seeding the example catalogue is opt-out** (`GATEWAY_SEED_DEFAULTS=false`) for a real
  deployment.
- **CI** runs on `ubuntu-26.04` with `azure/setup-helm` v5.1.0 (Node 24).

## Fixed

- **Security (external pentest):** three findings closed, including a timing oracle on API
  key rejection and an admin limiter that could be bypassed via the origin. API-key
  guessing is budgeted and rejected responses are never cached, so a wrong key cannot be
  turned into a cache oracle.
- **Security:** a provider API key is never written into the audit log; the proxy-auth
  startup warning now actually fires.
- Health no longer reports DOWN when no SMTP host is configured.
- The end-to-end suite authenticates its Prometheus check instead of failing with a 401.
- The Dokploy compose no longer uses `env_file`, which broke the deployment.

## Database

- `V19__usage_cache_tier.sql` adds `usage_records.cache_tier` (`exact`, `semantic`, or null).
- `V20__provider_vertex.sql` adds `providers.project` and `providers.location` and widens
  `api_key_cipher` to hold a service-account JSON.

Both run automatically on startup. The partitioning script in
[`deploy/postgres/partitions.sql`](deploy/postgres/partitions.sql) is separate and opt-in:
it rewrites `usage_records`, so it is documented as a maintenance-window step after a
`pg_dump`.
