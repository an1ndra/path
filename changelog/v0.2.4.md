# v0.2.4

A small release about first-run honesty: a real deployment no longer starts with a
catalogue of providers it has no credentials for.

Until now `GATEWAY_SEED_DEFAULTS` defaulted to `true`, so the first boot of an empty
database created `openai`, `anthropic`, `groq` and `gemini` plus a starter route table.
Those rows carried no keys, so every call through them failed, and the console showed
them as if they were configured. Deleting them did not help for long: the seeder looked
each provider up by slug on every boot and recreated any that were missing.

Nothing changes for an existing database that already has providers and routes. To clear
the examples out of one that has them, follow
[`docs/OPERATIONS.md`](../docs/OPERATIONS.md#removing-the-example-catalogue).

## Changed

- **Seeding is off by default.** `GATEWAY_SEED_DEFAULTS` now defaults to `false`, and
  `GatewayProperties.seedDefaults` matches it, so a fresh gateway has an empty catalogue
  and the console is where providers, routes and keys are added. Set the variable to
  `true` for a throwaway demo instance.
- **The example catalogue only fills an empty catalogue.** The seeder requires both the
  provider and the route table to be empty, and it no longer looks providers up by slug,
  so it cannot resurrect one that was deleted.
- **`deploy/dokploy/compose.yml` passes `GATEWAY_SEED_DEFAULTS` through** with a `false`
  default. Docker Compose only injects a variable the compose file interpolates, so the
  line in Dokploy's Environment editor never reached the process and the seeder kept
  running with its built-in default.
- `README.md`, `docs/CONFIGURATION.md`, `docs/OPERATIONS.md` and
  `deploy/dokploy/README.md` describe the new default, the ready-made base URLs for
  ChatGPT, Gemini, OpenCode and the other common upstreams, and how to delete the example
  rows from a database that already has them.

## Fixed

- A provider deleted in the console stays deleted across restarts. Previously it came back
  on the next boot whenever the seed flag was on.

## Tests

- New `SeedNoResurrectionTest`: deleting an example provider and running the seeder again
  leaves it deleted, and a second seed run does not duplicate rows.
- The suites that assert on the example catalogue (`GatewayApiTest`, `AliasServiceTest`,
  `RoutingTest`, `PublicModelsTest`) now opt in with `gateway.seed-defaults=true` instead
  of relying on the default.
