# v0.2.5

One fix: the GEMINI and VERTEX provider types could not be created.

## Fixed

- **Creating a `GEMINI` or `VERTEX` provider no longer fails.** V1's
  `providers_type_check` constraint only allowed `OPENAI` and `ANTHROPIC`, and v0.2.3
  added the two new wire formats to the enum and the admin API without a migration for
  the constraint. `POST /admin/providers` with `"type":"GEMINI"` (or `VERTEX`) answered
  500 `internal_error` on Postgres, and the console's Add Provider dialog failed the same
  way. The new V21 migration finds the check constraint through `information_schema`
  (its name differs between Postgres and H2) and replaces it with one that lists all four
  types.
- `ProviderTypeConstraintTest` inserts one provider per wire format, so a constraint that
  drifts behind the enum fails the build instead of production.

Nothing else changed. v0.2.4's release notes cover the seeding change; deployments that
already run v0.2.4 only need this for native Gemini or Vertex.
