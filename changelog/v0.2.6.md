# v0.2.6

Fixes the v0.2.5 migration, which crash-looped a Postgres deployment.

## Fixed

- **V21 no longer crash-loops the gateway on Postgres 16.** v0.2.5 found the provider type
  constraint by listing every `CHECK` constraint on `providers` and dropping it. Postgres
  16 also reports `NOT NULL` as a `CHECK` constraint in
  `information_schema.table_constraints`, with a synthesized name such as
  `2200_16395_1_not_null` that cannot be dropped: the migration failed, Flyway rolled it
  back, and the container restarted into the same failure. V21 now joins
  `information_schema.check_constraints` and drops only the constraint whose clause
  mentions `OPENAI`, so the type check is the only candidate. On Postgres the synthetic
  `NOT NULL` rows do not appear in `check_constraints` at all, so the join excludes them
  even before the clause filter.
- No schema change beyond v0.2.5's intended one: the `providers` type check still ends up
  listing `OPENAI`, `ANTHROPIC`, `GEMINI` and `VERTEX`.

If a deployment was left crash-looping by v0.2.5, deploying v0.2.6 is enough: the failed
migration was rolled back, so Flyway runs the corrected V21 on the next boot. No manual
database step.
