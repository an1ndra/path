# v0.2.7

OpenCode Go works through the gateway.

## Fixed

- **Requests to an OpenCode provider now carry `x-opencode-session`.** OpenCode Go
  rejects any request without it with 400 `upstream_invalid_request` ("cannot be routed
  efficiently"), which made every model on that provider uncallable through the gateway.
  The value is derived from the upstream model and the first user message, so one
  conversation keeps one id across retries, fallbacks and streaming, and a new
  conversation gets a new one.
- **Every OpenAI-compatible request identifies the gateway.** The upstream `User-Agent`
  was `Java-http-client/<version>`, which reads as a generic library; OpenCode's Go terms
  ask a client to name itself, so the header is now `path-gateway`.

Both changes are additive. Providers other than `opencode*` send the same headers as
before apart from the user agent.

## Notes

- `x-opencode-session` applies to slugs starting with `opencode`, matching the documented
  provider ids (`opencode`, `opencode-go`). A provider with a different slug pointed at
  OpenCode's endpoint needs one of those slugs or the header will be missing again.
