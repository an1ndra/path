# v0.2.8

Per-identity SSO scopes.

## Added

- **Per-identity SSO scopes.** `GATEWAY_PROXY_AUTH_SCOPES_HEADER` lets an authenticating
  reverse proxy send a scope header such as `X-Forwarded-Scopes` alongside the identity
  header. One SSO user can be read-only while another gets `read,write`. When the scope
  header is configured it is authoritative; a missing, empty or unsupported value fails
  closed instead of inheriting the broader `GATEWAY_PROXY_AUTH_SCOPES` default.
- **Read-only admin access is visible in the console.** `/admin/settings` returns the
  identity's scopes and `can_write`, so a read-only SSO user or `adm_...` token sees the
  console with write actions disabled.

## Changed

- Proxy scope parsing accepts only `read` and `write`; unknown values are rejected with
  `403 proxy_scope_invalid`.

## Notes

- Configure the proxy to send the scope header and strip any client-supplied
  `X-Forwarded-*` headers. The gateway must remain unreachable except through the proxy.
